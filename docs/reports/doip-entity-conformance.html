The audit

What the entity used to tell a tester

Judgement, not transcription

Four decisions worth arguing with

A functional group address reaches every ECU

Group membership is not modelled. Nothing in the vehicle model says which ECUs belong to which group, and no source it is built from — CAN log, capture, simulation file — carries it. Inventing a membership would be a claim the evidence does not support, so every group address reaches everything.

The limit belongs to the transport, not to the addressing mode

A functional request over seven bytes of user data is refused only when some ECU in the vehicle has no DoIP address of its own. That ECU is behind a gateway on CAN and the message has to cross it; a vehicle reached entirely over Ethernet has no SingleFrame to fit into and is not length-limited. On P33C this is observable because exactly one of its 47 ECUs is CAN-only.

The whole message is discarded, not partly delivered

Half a broadcast is worse than none: the tester has no way to learn which half arrived. The 46 ECUs that could have taken it get nothing.

An answer with no address to travel under is dropped

A CAN-only ECU's broadcast answer has nothing truthful for the source address field, so it is dropped — as a real gateway drops a reply it has no route back for. The request still reached it over CAN and its state still changed. What is lost is the answer, not the ECU.

On the wire

Two harnesses, both speaking ISO 13400-2 on a socket

Neither goes through the HTTP API, so what they exercise is the entity a real tester meets. The negative cases matter more than the positive ones: anything that answers correctly is easy to get right by accident, and what separates a conformant entity from a plausible one is whether it refuses properly.

What the capture-driven harness refuses to let pass

  • A diagnostic message before routing activation gets no answer and no NACK — and then the socket closes, between one and five seconds later. Both halves are asserted: the silence is REQ 3.DoIP-131 NL, and the close is what makes it legible to a tester instead of a hang.
  • An unknown target address is NACKed 0x03; a functional group address is not, and all six ECUs answer it.
  • A protocol version outside Table 16 gets a generic header NACK.
  • A vehicle identification response arrives, and inside the announce wait.

What the vehicle harness adds

  • Real data: a DID read and its value, DTCs filtered by status mask (and a narrow mask returning only what sets that bit), an unknown DID refused, security actually unlocked.
  • One ECU, two transports. A session entered over DoIP is visible on CAN; one entered over CAN is visible over DoIP; security unlocked either way is unlocked both ways. Two instances keyed separately would pass every other check in the file and diverge the moment a tester used both.
  • One broadcast reaching all 46 addressable ECUs, each answer under its own address — and the 47th, CAN-only, staying silent because it has none.
  • The same nine-byte request refused functionally (0x04) and accepted physically. That pair is the whole of REQ 7.DoIP-072 AL in two messages.

Stated, not implied

What is deliberately not built

  • Power-up announcement. The entity answers identification requests but does not announce itself unprompted. The three Table 12 parameters for it exist; nothing consumes them.
  • Alive-check arbitration. An entity may send an alive check to a socket holding a contested source address and free it if it does not answer. This one refuses with 0x03 instead — stricter than the standard permits, never looser. A tester is told "in use" where the standard would allow "in use", and never the reverse.
  • TLS on port 3496. Encrypted packets in a capture are counted and skipped, and the count is reported rather than hidden.
  • Authentication and confirmation states. The connection state machine has PendingAuthentication and honours its timer correctly, but nothing drives it there except a forced routing activation code.
  • Functional group membership. See above — a decision, not an omission.
