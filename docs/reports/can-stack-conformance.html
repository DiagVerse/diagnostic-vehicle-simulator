Layer by layer

Where the stack sits against the standards

Three layers carry a UDS request from the wire to a virtual ECU. Each is a separate crate, and each is complete in different degrees — stated here rather than implied.

Stripe encodes coverage: implemented · partial · not built
LayerStandardCoverageWhat is there, and what is not
CAN frame ISO 11898 partial Classic CAN, 11-bit and 29-bit identifiers, DLC 0–8. CAN-FD is modelled in the frame type but never produced — the SLCAN path always sets it false. Error and remote frames are not simulated.
ISO-TP ISO 15765-2 implemented All four PCI types (SingleFrame, FirstFrame, ConsecutiveFrame, FlowControl), both directions. BlockSize, STmin in both units, wait-frame limit, overflow refusal, sequence validation with wrap, configurable padding.
Addressing ISO 15765-2 §10 partial Normal 11-bit and normal-fixed 29-bit (18DA<target><source>), plus functional broadcast. Extended and mixed addressing are not built.
UDS ISO 14229-1 partial Eleven services answered natively; the rest reachable only through a response override. Session and security state are real, not replayed.
UDS timing ISO 14229-2 §7 implemented P2, P2*, P4 advertised and honoured, with the ResponsePending sequence the standard requires when an answer runs past P2.
Transport SLCAN / LAWICEL implemented Streaming line codec, real serial ports, pseudo-terminals for a tester on the same machine, and in-memory loopback for tests.

A service marked override only is not unreachable — a response override answers it, and an override outranks the supported-service list by design. What it does not have is behaviour: no state changes, no computed reply.

Every parameter, and what changing it does

Three kinds of value sit together and are kept apart by name: what the ECU advertises (ISO 14229-2), what the operator injects to provoke a tester, and the ISO-TP flow control — the only group that governs the request direction.

P2Server_max14229-2 T350 msDeadline to start answering after the request is fully received. Advertised in the 0x10 response at 1 ms resolution.

The finding that drove most of this

Why BlockSize 0 failed, and why it was never a sequencing bug

A 386-byte SecurityAccess key kept arriving with holes in it. The sequence numbers came out 1…15 in order, then 3, 12, 4, 13, 5 — which reads as two interleaved streams, and had the tester's VCI blamed for sending out of order.

Proven, not argued: a test injects a 386-byte request — FirstFrame plus 55 ConsecutiveFrames — all at once on a bus that drops nothing, with BlockSize 0. It reassembles whole and is answered. The engine was correct throughout.

What was wrong is that the engine advertised 30 00 00 anyway — the server telling a tester "send everything, I can take it" over a gap where it cannot. The bridge now knows both speeds and, for an ECU asking for no pacing at all, advertises the slowest STmin the link can honour. An operator who states a BlockSize or STmin is obeyed; a link with room to spare is untouched.

Why it invented them

Correlation pairs a request with an answer on the strength of a single byte: a positive response is the service identifier plus 0x40. On a bus carrying thousands of periodic frames a second that coincidence is routine, and nothing downstream questioned it. Three guards now close it:

  • A request and its response can never share an identifier. A tester transmits on one, the ECU answers on another.
  • The service list is the 27 SIDs ISO 14229-1 defines, not two contiguous ranges that swept in every undefined value between them.
  • An ECU must be supported by evidence — something it revealed (a DID, a DTC, a security level, a session beyond the default), or an exchange sent to an address reserved for diagnostics, where coincidence cannot occur. Repetition was considered and rejected: periodic frames repeat by the thousand.

All 34 existing reconstruction tests still pass, and the real 47-ECU OEM vehicle still reconstructs — it earns its place on what it revealed.

Known gaps

Deliberately not built

  • CAN-FD on the wire. The frame type carries an FD flag; the SLCAN path never sets it. A 64-byte FirstFrame escape is not implemented.
  • Extended and mixed ISO-TP addressing. Normal 11-bit, normal-fixed 29-bit and functional broadcast only.
  • Seventeen of twenty 0x19 sub-functions, and routines that actually run under 0x31. Both refuse honestly rather than inventing data the model does not hold.
  • Raising a dongle's UART. Detection finds the rate an adapter is already running at; it cannot make one faster. The MINI2024042 answers no identity command, so its speed falls back to an assumed 115 200 — settable by hand in the Hardware tab.
  • Error and remote frames, and bus-off simulation.
